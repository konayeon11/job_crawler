# 데이터베이스 설계: '기억' 기능 구현

## 1. 목표

에이전트가 사용자와의 상호작용을 기억하여 개인화된 경험을 제공하고, 데이터를 지속적으로 관리할 수 있도록 '기억' 기능을 구현합니다.

- **개인화:** 사용자의 알레르기, 선호 음식, 다이어트 목표 등을 저장하고 반영합니다.
- **지속성:** 재고 상태를 유지하여, 매번 새로 스캔하는 대신 기존 재고를 업데이트합니다.
- **장기 분석:** 식단 히스토리를 기록하여 장기적인 영양 분석 및 피드백을 제공합니다.

## 2. 데이터베이스 선택: SQLite

프로젝트의 초기 단계에서는 **SQLite**를 사용합니다.

### SQLite를 선택한 이유

- **단순성 및 편의성:** 별도의 서버 설치나 복잡한 설정 없이, 프로젝트 내에 단일 파일로 데이터베이스를 관리할 수 있습니다. 파이썬에 기본적으로 내장된 `sqlite3` 라이브러리를 사용하므로 추가 의존성이 없습니다.
- **휴대성:** 데이터베이스가 파일 하나이므로 개발, 백업, 이동이 매우 편리합니다.
- **충분한 성능:** 개인 사용자를 위한 데이터(설정, 재고, 기록)를 처리하기에 충분한 성능과 안정성을 제공합니다.

### 고려된 다른 옵션들

- **PostgreSQL, MySQL:** 여러 사용자가 동시에 접속하는 대규모 서비스에 적합한 강력한 데이터베이스 서버입니다. 현재 프로젝트 단계에서는 설정과 관리가 복잡하여 오버헤드가 큽니다.
- **NoSQL (e.g., MongoDB):** 데이터 구조가 비정형적이거나 유연해야 할 때 유용합니다. 하지만 본 프로젝트의 데이터는 관계가 명확하므로 관계형 데이터베이스인 SQLite가 더 직관적입니다.

> **결론:** SQLite는 '기억' 기능을 빠르고 효율적으로 프로토타이핑하기 위한 최적의 선택입니다. 추후 애플리케이션의 규모가 커지면 보다 강력한 데이터베이스로 마이그레이션하는 것을 고려할 수 있습니다.

## 3. 데이터베이스 스키마

다음과 같이 3개의 테이블을 설계하여 데이터를 관리합니다.

### `user_preferences`

사용자의 기본 설정과 제약 조건을 저장합니다.

| Column | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `user_id` | TEXT | 사용자 ID (PK) | `default_user` |
| `allergies` | TEXT | 알레르기 정보 (JSON) | `["땅콩", "갑각류"]` |
| `preferences` | TEXT | 선호/기피 음식 (JSON) | `{"likes": ["생선"], "dislikes": ["가지"]}` |
| `dietary_goals`| TEXT | 다이어트 목표 | `low_sodium` |

### `inventory`

식료품 재고를 관리합니다.

| Column | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `item_name` | TEXT | 재료명 (PK) | `계란` |
| `quantity` | TEXT | 수량 | `10개` |
| `added_date` | TEXT | 추가된 날짜 | `2025-10-20` |
| `expiry_date` | TEXT | 유통기한 | `2025-11-03` |

### `meal_history`

사용자가 섭취한 식단 기록을 관리합니다.

| Column | Type | Description | Example |
| :--- | :--- | :--- | :--- |
| `meal_id` | INTEGER | 식사 기록 ID (PK) | `1` |
| `meal_date` | TEXT | 섭취 날짜 | `2025-10-21` |
| `recipe_id` | TEXT | 레시피 ID | `c784a8e88af4f57f` |
| `recipe_title` | TEXT | 레시피 제목 | `아보카도 토르티야 랩` |
| `ingredients` | TEXT | 사용된 재료 (JSON) | `["토르티야", "아보카도"]` |
