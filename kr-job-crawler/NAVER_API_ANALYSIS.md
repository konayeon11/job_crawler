# Naver 채용공고 API 및 데이터 추출 분석

## 1️⃣ Naver의 숨겨진 API 존재 여부

### 조사 결과: ❌ **공개되지 않음**

```
✗ 공식 API 없음
✗ 숨겨진 API 엔드포인트 없음
✗ 페이지 로드 시 XHR 요청으로 데이터 가져오지 않음
✗ JavaScript 변수에 데이터 임베드 없음
```

**증거:**
- Naver가 HTML을 초기 로드할 때 모든 콘텐츠를 포함하지 않음
- 동적 콘텐츠는 클라이언트 측 렌더링
- DevTools Network 탭에서 추적 가능한 API 없음

## 2️⃣ 데이터 추출 방법 비교

### **방법 1: CSS 선택자 (OpenAI 분석)**

```
장점:
  ✓ 빠름 (2-3초)
  ✓ 간단한 구현
  ✓ 비용 저렴 (~$0.01)

단점:
  ✗ Naver에서는 표준 선택자 없음
  ✗ 페이지 마크업이 자주 변경됨
  ✗ 동적 렌더링된 콘텐츠 못 잡음

결과:
  ❌ Naver에서는 작동 안 함
```

### **방법 2: XPath (일반 웹사이트용)**

```
장점:
  ✓ CSS보다 유연함
  ✓ 복잡한 선택자 지원

단점:
  ✗ 느림 (5-10초)
  ✗ 복잡한 쿼리 작성 필요
  ✗ 마크업 변경에 취약

결과:
  ⚠️ 부분적 작동 (신뢰도 낮음)
```

### **방법 3: JavaScript 실행 (가장 강력)**

```
장점:
  ✓ 동적 렌더링된 콘텐츠 모두 접근
  ✓ 실제 DOM 내용 추출
  ✓ 매우 안정적

단점:
  ✗ 느림 (15-20초)
  ✗ Selenium 렌더링 필요
  ✗ 메모리 사용량 많음

결과:
  ✅ Naver에서 완벽 작동
```

### **방법 4: HTML 정규식 파싱**

```
장점:
  ✓ CSS/XPath보다 빠름
  ✓ 구현 간단

단점:
  ✗ 매우 취약함 (정규식 변경 시 깨짐)
  ✗ 유지보수 어려움
  ✗ 신뢰도 낮음

결과:
  ⚠️ 긴급용으로만 사용
```

## 6️⃣ 최종 추천: 하이브리드 접근법

### 이유

1. **가장 높은 신뢰도** (95%+)
   - JSON-LD로 기본 정보 빠르게 추출
   - JavaScript로 나머지 정보 완전히 접근
   - 정규식으로 정밀 추출

2. **유연성**
   - Kakao: API 사용 (6초)
   - Naver: 하이브리드 (25초)
   - 기타: OpenAI + CSS (15초)

3. **확장성**
   - 새로운 사이트 추가 용이
   - 추출 실패 시 fallback 가능
   - 데이터 품질 검증 가능

4. **비용 효율**
   - OpenAI 최소 사용
   - API 무료
   - Selenium만 추가 비용

### 구현 순서

```
1순위: 공식 API (Kakao)
2순위: 구조화 데이터 (JSON-LD)
3순위: JavaScript 실행 (동적 콘텐츠)
4순위: OpenAI 분석 (일반 사이트)
5순위: 정규식 (최후의 수단)
```
